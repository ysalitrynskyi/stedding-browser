# Stedding 0.4.0 beta 18

Spaces can share one session: several Spaces on the same sign-ins and site data, the way Arc's
Spaces share a profile. On Chromium 157.0.8103.51.

## New

- **Spaces that share a session (GitHub issues 8 and 99).** A Space's session can now be one
  that other Spaces use. Spaces in one session share sign-ins, cookies and site data, in every
  window and after a restart, and each keeps its own tabs, name and colour. Choose it in Edit
  Space or in Settings › Stedding › Spaces: Shared, a session that is already there, or
  **New session…** with a name. A session's data is deleted only when no Space uses it any more,
  and Settings lists a session no Space uses, with **Delete Session…**. Spaces in one session
  share their essentials and wear the same mark. Export, import and sync carry a named session.

## Fixed

- **The address row under a page's own dialog (GitHub issue 101).** When a page dims itself
  under a dialog, as Discord does for a profile, the address row went grey with it. It now keeps
  its colour and follows the page again once the page really changes.
- **Password managers in a peek (GitHub issue 102).** An extension could not reach the page of
  a peek, so a password manager could not fill a login there. It now can.
- **Undo after closing a tab, with VoiceOver.** The toast's Undo is read as a button.
- **⌘D in a private window on the Mac** bookmarks the page; it did nothing.
- **Windows: the address row's end moves the window.** The strip just before the window's
  buttons is part of the title bar, so a drag there moves the window.
- **A pinned tab's child tabs** are drawn whole; their icons were cut on the left.
- **Sidebar sync:** a pin that a synced Space deletion had opened goes to Recently Closed when
  the other computer removes it; it stayed open.

## Security

- No change: Chromium 157.0.8103.51, as in beta 17.

## Install

- **macOS** (Apple silicon, macOS 13 or later): `Stedding-0.4.0-beta.18-arm64.dmg`, signed and
  notarized. Open it and drag Stedding to Applications.
- **Windows** (10 and 11, x64): `Stedding-0.4.0-beta.18-win-x64.exe`, installs for you alone.
  It is not signed yet: in SmartScreen click **More info**, then **Run anyway**, once.

Installed copies update themselves (Mac from 0.2.0 beta 16, Windows from 0.2.0 beta 19).

## Known limits

- The Windows installer is unsigned (`S-56`).
- Netflix, Disney+, Prime Video and Spotify's web player do not play yet (`S-270`).
- Spaces that share a session share their essentials; a Space's own essentials with shared
  sign-ins are not offered (GitHub issue 87, `S-445`).
- In a peek, an extension's toolbar button still acts on the pinned tab under it: Bitwarden's
  popup lists that site's logins. Open as Tab gives the extension the page (`S-469`).
- Finished downloads missing from the Downloads list (GitHub issue 90) are not understood yet; the
  steps that lead there would help.
- Sync through WebDAV or S3 was checked against local servers, not yet a commercial service. A
  server that only offers Digest sign-in is refused, and S3 uses path-style addresses.
- Arc's splits, archive and pinned folders were built from public descriptions of Arc's files and
  checked on files made to match them, not yet on a real Arc profile.
- Import from Opera was checked on files made to match Opera's, not yet on a real install.
- Dia's sidebar does not come across: Dia keeps it in an encrypted database.
- Making a real passkey with a finger on Touch ID was not tried.
- Chromium's tab search still jumps to a page in another window, with no question.
- Chromium's built-in list of sites that must load over HTTPS lapses for this build on
  10 January 2027; a release on a newer base comes before then.

## How it was checked

- **The fixes:** a browser test or unit test for each, seen failing first on Windows' release
  build and passing after. Then the release builds by eye on both platforms, light and dark: a
  page's black layer at 60% under its own card, with the row keeping the header's blue; Edit
  Space and Settings with two Spaces in one session, their marks, and a session no Space uses
  with **Delete Session…**. On the Mac, through the accessibility API, the toast after a close
  reads "“Inbox” closed" and its Undo is a button.
- **Suites:** on the Mac, 1523 unit tests and 984 browser tests on the release build and on the
  build with DCHECKs and the dangling-pointer detector. All passed on the release build; on the
  DCHECK build one sync test timed out in the parallel run and passed five times of five alone.
  Its wait was a race in the test, now closed. On Windows, 1511 unit tests on every build, all
  passing, and 930 browser tests. All passed on the release build. On the DCHECK build, one
  test's private window could not connect when the PC ran out of network buffers late in the
  run; it passed three times of three alone.
- **AddressSanitizer on Windows:** the unit and browser suites all passed, with no
  AddressSanitizer report and no dangling pointer.
- **Acceptance scripts:** the core loop, the drags and the keyboard script, on a copy of the
  notarized Mac build and on the installed Windows copy. On the Mac a clipboard manager took ⇧⌘C
  from the keyboard script; alone, ⌃⌘N opened its split and Copy Link showed its toast. On
  Windows, run right after the installer's cycle, the core loop's and the drags' setup did not
  move pages into the other Spaces; alone, the core loop passed all fourteen steps and the drags
  all five. The keyboard script passed all twenty.
- **Updates:** from beta 17 to beta 18 on both platforms through a local feed, the same files
  users get, with the sidebar's width kept on Windows; and on Windows the installer's upgrade,
  uninstall and fresh install.
