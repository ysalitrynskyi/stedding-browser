# Feature: Apps made from pages

Status: **Wa1–Wa7, Wa9–Wa15, Wa18, Wa20, Wa21 and Wa23 built. Wa8 is Chromium's Windows install, with no Stedding test. Wa16, Wa17 and Wa22 are not checked on a real update or launch. Wa19 is not built.**

A page Chromium can make an app of can become an app: a window with no browser around it, an icon in the Dock or the Start menu, and the session of the Space it was made in. On the Mac the command is "Add to Dock…". On Windows it keeps Chromium's "Install page as app…". A page with an installable manifest installs as that app; any other page is a do-it-yourself app named in the dialog. Nothing is fetched but what the page itself names.

Stedding's changes to Chromium's web apps:

- The command is also in the File menu on the Mac and in the command bar (`IDC_STEDDING_MAKE_APP`). The Dock tile is added, and no Finder window opens.
- The app keeps the cookie jar of the Space it was made in (Wa11–Wa15, ADR 0025).
- The app window is edge to edge (Wa9). Launchers go in `~/Applications/Stedding Apps.localized` (Wa7).
- Links into an app's scope are not captured until the user turns that on for the app (Wa15).

Neither platform has a chord for it. On Windows there is no menu bar; the Start menu takes the place of the Dock and the launcher.

Owner docs: `docs/PRODUCT.md` (Progressive Web Apps), `docs/PRIVACY.md` (Apps made from pages), `docs/decisions/0019-space-sessions-are-storage-partitions.md`, `docs/decisions/0025-apps-keep-their-spaces-session.md`. Patch 0072, with Wa23 in patch 0075.

## Decisions

The build follows these. ADR 0025 is decision 2.

1. The Mac command is "Add to Dock…" and a real Dock tile. The Dock restarts once (Wa1, Wa7).
2. The app keeps its Space's session (ADR 0025, Wa11).
3. The installing tab moves into the app, except the tabs Wa6 keeps in the sidebar.
4. Capturing is off for every app until that app's settings turn it on (Wa15).
5. Every Mac install the user starts adds the tile, the address row's icon included (Wa7).
6. Removing an app removes the tile Stedding added (Wa18).
7. "Manage Apps" is a command-bar row. There is no Settings list of apps.
8. The menu still says "Create shortcut…" (Wa21).
9. The command bar matches extra words from a word's start (commandbar K10, Wa1).
10. Launchers made before the move into "Stedding Apps" are not rebuilt there (BACKLOG S-171). Not done.
11. The dialog says "Opens with the session of “Work”." (Wa5).
12. A Mac tile goes right after the last browser tile, newest first (Wa7).
13. "Open in Stedding" for a shared-jar page, when every Space keeps its own session and no Blank Window is open, opens a new Blank Window (Wa14).

## Notes

The records live in `chrome/common/stedding/web_apps.h`, written through `chrome/browser/web_applications/web_app_jar_record.cc`. The jar answers are `chrome/browser/ui/spaces/app_jar.cc`. The command is `chrome/browser/ui/stedding/make_app.cc` and `make_app_rules.cc`. The Dock is `chrome/browser/ui/stedding/app_dock_mac.mm`. `stedding::AppRecordsKeeper` drops the records when the app is removed.

macOS screen-share audio does not treat Stedding's apps as this browser: `content/browser/media/capture/desktop_capture_util_mac.mm` lists `org.chromium.Chromium` (`docs/ARCHITECTURE.md`, "Three identifiers do not follow `MAC_BUNDLE_ID`").

BACKLOG S-90 is a different thing: chords inside a page, such as Google Docs, not an app made from a page.
