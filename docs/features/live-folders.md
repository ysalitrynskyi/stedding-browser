# Feature: Live folders (GitHub pull requests)

Status: **Lf1–Lf13 built** (the 0.6.0 patch, not yet in a release; ADR 0036 lets it move to the next release if it misses the gate). Checked on Windows: the unit and browser tests below pass on `win-release`, and the Live Folders suites on `win-checks`. The Mac's suites and a pass on a real build with a real token are owed.
Owner: `docs/PRODUCT.md` (Live Folders), `docs/decisions/0036-live-folders-for-github.md` (option B), `docs/PRIVACY.md`, BACKLOG S-478, GitHub discussion 106.

A live folder is a pinned folder of a Space whose rows Stedding keeps up to date from somewhere else. The first and only source is GitHub: the open pull requests the person opened, is assigned, is asked to review or is mentioned in, read from GitHub's REST API with a fine-grained, read-only token the person makes on github.com and pastes once. It is off until the person makes it, and nothing appears by itself. Arc read GitHub's web pages through the signed-in session and broke when GitHub changed them; the API is documented and versioned (ADR 0036).

One live folder per profile in this slice. GitHub Enterprise on its own domain, and other sources (an RSS or Atom feed), come later with decisions of their own.

## Design

- **The service.** `live_folders::LiveFolderService`, a profile service made with the profile (`chrome/browser/ui/live_folders/`). Off, it reads its setup and does nothing else: it observes no window and makes no request.
- **Where the rows live.** The folder is a pinned folder in the profile's pin store (`spaces::PinStore`, ADR 0035): each pull request is one Space-pin record whose folder path names the live folder. Every window that follows the registry shows it through its `PinMirror`, asleep until chosen, as it shows any pinned folder (windows G2, G13). The service is the only writer of those records' content; it publishes them into the store and never touches a window.
- **What is stored.** The setup, `stedding.live_folders.github` (a profile preference): on, the Space, the folder's id, the rows the person removed, the last refresh's time and failure. The token, `stedding.live_folders.github_token`: sealed with the system's key store through `os_crypt_async` (the Keychain on the Mac, DPAPI on Windows), as sync's sign-in to a place is (sidebar-file Sf55), base64. Neither preference is on the list Settings' page may read (`settings_private::PrefsUtil`), and both stay on this computer (settings sync leaves them out).
- **Where requests go.** `https://api.github.com/search/issues` alone, through the browser's own network context (`SystemNetworkContextManager`), as sync's places do: no cookies (credentials omitted, `LiveFoldersTest.TheTokenReachesNoPageNorSettings`), no cache shared with pages, and nothing an extension's `webRequest` sees (no test; it follows from the browser's own network context, which no extension's `webRequest` observes). A redirect off `api.github.com` drops the Authorization header. The traffic annotation is `stedding_live_folder_github`.
- **Reading answers.** `base::JSONReader` (memory-safe) on at most 2 MiB per answer. An item is kept only if it is a pull request, open, with a node id of letters, digits and `_ - + / =` (at most 128), at `https://github.com/<owner>/<repo>/pull/<n>`.
- **Row identity.** A row's tab token is `livegh-` and GitHub's node id of the pull request. That prefix is how sync knows a live row (`live_folders::IsLiveRowToken`), and the folder's id how it knows the folder (`live_folders::IsLiveFolder`). A tab that stops being a row (removed by the person, or left after the folder went) takes a random token at once, so the prefix never marks a tab of the person's.
- **The minute's floor.** `live_folders::LiveFolderScheduler`: a 10-minute beat, and asks from a window coming to the front or a Refresh, never more than once a minute.

## Notes

- The first list, the refresh and the token's check are one request path; there is no separate "test token" call.
- A row is a Space pin of the profile's store; asleep it has no renderer (windows G22). 50 rows are 50 asleep tabs per window at most.
- GitHub's search API allows an authenticated token 30 requests a minute (GitHub's docs, ["REST API endpoints for search", Rate limit](https://docs.github.com/en/rest/search/search#rate-limit)); a refresh is four, and at most one refresh runs a minute.
- The traffic annotation is not yet in `tools/traffic_annotation/summary/annotations.xml`; neither are Stedding's other two (sync's places, the Windows updater).
- Export of a Space (sidebar-file) still writes the live folder's rows as ordinary pins; leaving them out there is open.
