# Stedding 0.4.0 beta 12

Sidebar sync through your own WebDAV or S3 storage, and fixes for private windows, the folder's −
and little windows. Still on Chromium 157.0.8103.39.

## New

- **Sync through WebDAV or S3 storage.** Sync can now go through WebDAV or S3 storage you already
  have, as well as a folder. Type the address and your own sign-in, and Stedding tests the place
  before anything starts. The sign-in stays encrypted on this computer, and nothing for it ships
  with the browser: no provider, no account and no key. It is off until you set it up, in
  Settings › Stedding › Sync and import (GitHub issue 77). There is no sign-in to Google Drive,
  Dropbox or OneDrive: for those, a folder their own app keeps works as before.

## Fixed

- **Private windows follow your settings.** A private or Guest window kept the address row when
  the address was in the sidebar or the row was hidden. It now follows those settings, and
  Ctrl+Shift+D works there (GitHub issue 83).
- **A crash when a tab closed under the pointer.** Closing a tab with the pointer over a Space's
  icon could stop the browser.
- **The − buttons.** The − on a folder and on a pin sits in the middle of its hover circle, and the
  circle is as big as it should be, wider than a favicon (a comment on GitHub issue 78).
- **A folder's − leaves the list where it is.** With a lot of tabs the list jumped to the next
  open row, far down. The header now stays under the pointer.
- **The circle behind the shield and the moon** is a little bigger, the size of the chips beside
  it.
- **A little window keeps its size.** After a second restart it came back as big as the main
  window, over it.
- **The notice on sites that need DRM** fits a narrow window, and it no longer waits behind
  another bar.
- **Keys after a rename.** Enter or Escape in a rename left the keys in the address field, with the
  address selected, on the Mac. They go back to the page.

## Install

- **macOS** (Apple silicon, macOS 13 or later): `Stedding-0.4.0-beta.12-arm64.dmg`, signed and
  notarized. Open it and drag Stedding to Applications.
- **Windows** (10 and 11, x64): `Stedding-0.4.0-beta.12-win-x64.exe`, installs for you alone.
  It is not signed yet: in SmartScreen click **More info**, then **Run anyway**, once.

Installed copies update themselves (Mac from 0.2.0 beta 16, Windows from 0.2.0 beta 19).

## Known limits

- The Windows installer is unsigned (`S-56`).
- Netflix, Disney+, Prime Video and Spotify's web player do not play yet (`S-270`).
- Sync through WebDAV or S3 was checked against local servers, not yet a commercial service. A
  server that only offers Digest sign-in is refused, and S3 uses path-style addresses.
- Arc's splits, archive and pinned folders were built from public descriptions of Arc's files and
  checked on files made to match them, not yet on a real Arc profile.
- Import from Opera was checked on files made to match Opera's, not yet on a real install.
- Dia's sidebar does not come across: Dia keeps it in an encrypted database.
- This build is on Chromium 157.0.8103.39.
- Chromium's built-in list of sites that must load over HTTPS lapses for this build on
  10 January 2027; a release on a newer base comes before then.

## How it was checked

- **Suites:** on the Mac, 1484 unit tests and 891 browser tests on the release build and on the
  build with DCHECKs and the dangling-pointer detector. On Windows, 1472 and 840 on the same two.
  All passed.
- **AddressSanitizer on Windows:** the unit and browser suites, with no AddressSanitizer report and no
  dangling pointer.
- **Acceptance scripts:** the core loop on an installed Windows copy and on a copy of the notarized
  Mac build, all passing. One part on Windows failed right after the installer cycle and passed 14
  of 14 alone, as it has before.
- **Updates:** from beta 11 to beta 12 on both platforms through a local feed, the same files users
  get, with the sidebar's width kept on Windows.
- **Sync:** through Settings on the real builds, against a local WebDAV server on both platforms and
  a local S3 server on Windows. A separate read of the code found nine faults before release, all
  fixed with tests.
