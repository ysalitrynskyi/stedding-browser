# Stedding 0.4.0 beta 14

A closed pinned tab stays closed, Copy Link in a peek copies the peek's page, and a Settings switch
for how ⌘Q quits. Still on Chromium 157.0.8103.39.

## New

- **Copy Link in a peek.** The peek's bar has its own Copy Link button, first in the row. A click
  copies the page's link, and an Option-click (Alt on Windows) copies it as a Markdown link
  (GitHub issue 86).
- **Hold ⌘Q to quit, in Settings.** On the Mac, Settings › Stedding › Pages and menus has **Hold ⌘Q
  to quit**. On, a tap of ⌘Q shows a reminder and holding the keys quits. Off, ⌘Q quits at once. It
  is the same switch as **Warn Before Quitting** in the Stedding menu, which was the only place it
  was before (GitHub issue 88).

## Fixed

- **A closed pinned tab came back.** A pin closed with ⌘W (Ctrl+W on Windows), its − or a middle
  click was shown again, and woken, by the next close. A tab you put away, a closed pin or a tab put
  to sleep with Sleep Tab, now leaves the Space's list of tabs used recently, so the next close shows
  the tab you used before it. A tab that falls asleep on its own keeps its place (GitHub issue 85).
- **Copy Link over a peek.** ⇧⌘C, ⌥⇧⌘C and the address field's link button copied the pinned page
  under a peek. While a peek is open they copy the peek's page (Ctrl+Shift+C and Ctrl+Alt+Shift+C on
  Windows).

## Install

- **macOS** (Apple silicon, macOS 13 or later): `Stedding-0.4.0-beta.14-arm64.dmg`, signed and
  notarized. Open it and drag Stedding to Applications.
- **Windows** (10 and 11, x64): `Stedding-0.4.0-beta.14-win-x64.exe`, installs for you alone.
  It is not signed yet: in SmartScreen click **More info**, then **Run anyway**, once.

Installed copies update themselves (Mac from 0.2.0 beta 16, Windows from 0.2.0 beta 19).

## Known limits

- The Windows installer is unsigned (`S-56`).
- Netflix, Disney+, Prime Video and Spotify's web player do not play yet (`S-270`).
- A Space that shares its session cannot have essentials of its own yet (GitHub issue 87, `S-445`).
- Sync through WebDAV or S3 was checked against local servers, not yet a commercial service. A
  server that only offers Digest sign-in is refused, and S3 uses path-style addresses.
- Arc's splits, archive and pinned folders were built from public descriptions of Arc's files and
  checked on files made to match them, not yet on a real Arc profile.
- Import from Opera was checked on files made to match Opera's, not yet on a real install.
- Dia's sidebar does not come across: Dia keeps it in an encrypted database.
- Making a real passkey with a finger on Touch ID was not tried.
- Chromium's tab search still jumps to a page in another window, with no question.
- This build is on Chromium 157.0.8103.39.
- Chromium's built-in list of sites that must load over HTTPS lapses for this build on
  10 January 2027; a release on a newer base comes before then.

## How it was checked

- **Suites:** on the Mac, 1491 unit tests and 908 browser tests on the release build and on the
  build with DCHECKs and the dangling-pointer detector. On Windows, 1479 and 858 on the same two.
  All passed. Four Copy Link tests on the Mac's release build timed out once among the others,
  and each passed alone.
- **AddressSanitizer on Windows:** the unit and browser suites, with no AddressSanitizer report and no
  dangling pointer.
- **Using the build:** on the signed Mac build, ⇧⌘C did nothing with the focus in a peek's page,
  which the tests had missed. That is fixed, with a test that presses the keys. Then each of the four
  copies from a peek took the peek's page, on the signed Mac build and on an installed Windows copy,
  light and dark.
- **Acceptance scripts:** the core loop on an installed Windows copy and on a copy of the notarized
  Mac build, all passing. One part on Windows failed right after the installer cycle and passed 14
  of 14 alone, as it has before.
- **Updates:** from beta 13 to beta 14 on both platforms through a local feed, the same files users
  get, with the sidebar's width kept on Windows.
