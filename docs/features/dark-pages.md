# Feature: Dark pages

Status: **Dk1–Dk6, Dk8–Dk22 and Dk24 built** (patch 0072; on macOS and Windows, BACKLOG S-100). **Dk7 partial**: the content area and the commit-time preference are tested; the frame-by-frame check `dk_no_flash_light` has no recorded run. **Dk23 partial**: the cost on a heavy page is TBD. The app menu has no row (the owner's call). The named live checks in `docs/features/acceptance.md` have no recorded run.
Owner docs: `docs/PRODUCT.md` ("Dark mode for web pages"), `docs/PRIVACY.md`. Patch: `0072`.

One switch turns every website dark, in every window and Space of the profile, until it is turned off. It is Chromium's own automatic dark mode for web contents (`prefs::kWebKitForceDarkModeEnabled`), not an injected stylesheet or a CSS filter. Blink draws bright backgrounds dark and dark text light at paint time. Pictures, video, canvas and the PDF page keep their pixels. A site with its own dark theme uses it. The switch is on or off (the owner): there is no "follow the window" mode.

The ways in are a moon button at the address row's right end, ⌥⇧⌘D, a command bar row, a Settings row, the page menu's per-site row, and, on the Mac, a View menu row. It repaints open pages in place, with no reload. Settings keeps exceptions: "all sites, except these" (the default) or "only these sites". The browser's own pages, DevTools and extension pages are never darkened.

Chords below are the defaults; the user can change them (shortcuts Z5, Z11). On Windows every chord is the Mac's with ⌘ read as Ctrl and ⌥⌘ as Ctrl+Alt. The full map is `docs/features/windows.md` N7.

## What it never touches

- The window's Light, Dark or System mode, the sidebar, the address row's controls, menus, the command bar, toasts and the Space colours. The address row's colour follows the page (Dk8).
- The browser's own pages, DevTools, extension pages, options pages and popups (Dk9).
- Pictures, video, canvas, WebGL, the PDF page, and printed output (Dk3, Dk11).
- The page itself: no stylesheet, script, filter or DOM change. The only things a page can see are Dk4's `prefers-color-scheme: dark` and the `canvas` colour Chrome documents.
- Cookies, storage, history and network requests.
- Chromium's forced colours ("Page colours", Windows contrast themes) are left as they are. How the two combine is a live check on Windows.

## Privacy

Dark pages makes no network request and sends nothing. What is stored: the switch and the button's setting in the profile's `Preferences` file; the mode and the two lists as the content setting's default and entries (`profile.default_content_setting_values.auto_dark_web_content`, `profile.content_settings.exceptions.auto_dark_web_content`). The content setting is marked unsyncable. Stedding's sync through a folder carries only the sidebar. The lists name sites the user chose and stay on the machine. Whether Delete browsing data ("Site settings") and Settings > Reset settings clear the lists has no test in the series.

A site chosen from a private window is held in memory for that session and never written to the profile (Dk21). Changing the switch from a private window writes the profile's switch, which names no site.

A page can learn that the reader prefers dark (Dk4), the same signal a dark window already gives, and, through Chrome's documented `canvas` trick, that automatic darkening is on. A site cannot read the lists. An embedded frame follows its top-level site.
