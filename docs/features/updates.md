# Feature: Updates

Status: **Up1–Up22 built** on macOS and Windows. Linux is not shipped (BACKLOG S-216).

On the Mac, Sparkle 2.10.0 checks the signed feed `updates/appcast.xml`, downloads a later version in the background, and installs it at quit (ADR 0022). On Windows the browser is the updater: it reads `updates/appcast-windows.xml`, signed with the Windows update key (ADR 0023, ADR 0026). Both feeds are served from GitHub. The site is not on the update path (ADR 0014). With "Update Stedding automatically" on (the default), each platform checks ten seconds after a launch when the last check is more than an hour old, and every six hours while it runs. No Sparkle window opens. The sidebar, the command bar, the About page and the app menu show what the updater is doing. After the install, and after each update, the browser opens one thank-you page on stedding.dev.

`tooling/fetch-sparkle` puts Sparkle at `third_party/stedding_sparkle/` in the checkout. `stedding::AppUpdater` is the one interface (`app_updater_mac.mm`, `app_updater_win.cc`). `tooling/publish-appcast` and `tooling/win/publish-appcast.ps1` offer a release after `tooling/publish-release`. On Linux the package system is the plan (ADR 0023); Chromium's upgrade detector does not run in this build, so a Linux pill cannot follow it.

Owner docs: `docs/decisions/0022-sparkle-updates-the-mac.md`, `docs/decisions/0023-updates-on-windows-and-linux.md`, `docs/decisions/0026-a-windows-update-key.md`, `docs/PRIVACY.md` (the update check), `docs/ROADMAP.md#the-quality-bar` (rollback).
