# Feature: Auto-archive

Status: **A1–A15 built.** Nothing is archived until the user picks a time (A6). A window the next launch opens again is not an archive row, and ⇧⌘T passes over it (A13, A15).

Unpinned tabs in a normal window that nobody has looked at for the chosen time close into Chromium's recently-closed list, so ⇧⌘T and History can bring one back. Pinned tabs, tabs in a folder, the tab on screen and a tab in use are never archived. The sweep is a per-window `TabArchiver` (`chrome/browser/ui/archive/`), every five minutes. Idle time is wall-clock time, stored on the tab as `stedding.archive.idle_since`, so time asleep and time the browser was closed both count. The threshold is `stedding.archive.idle_hours` (default 0, Never). Patches `0011`, `0028`, `0060`, `0067`, `0072`. On Windows, ⌘ is Ctrl (`docs/features/windows.md` N7).

## Limits

- `chrome.sessions.restore()` with no id still restores Chromium's most recent entry.
- Linux's global menu (`dbus_appmenu.cc`) and the action-based app menu (`RecentTabsBuilder`, behind `kAppMenuGlowUp`, off by default) still list a window the next launch opened again, and they do not group a folder close.
- Not mirrored: a profile that must sign in again keeps every window it closes and restores them all at the unlock, whatever the startup setting; those windows are not marked, so their tabs are rows beside the reopened ones. Only force-sign-in profiles get there.
