# Feature: Tracker-free defaults, one Privacy block

Status: **Q0–Q18 built.**
Owner docs: `docs/PRIVACY.md`, `docs/decisions/0017-privacy-defaults.md`. Patches: 0030; Q10's refresh features, 0042; Q11–Q13, 0062; Q14, 0065; Q15, 0089; Q16 and Q18, 0104.

`docs/PRIVACY.md` promises defaults Chromium does not ship with. Each promise is a preference default, and the controls sit in one Privacy block of chrome://settings/stedding. A row that Chromium already has binds Chromium's preference, so the eye icon, per-site cookie allowances and the permission prompts keep working. Global Privacy Control is Stedding's own preference.

## Notes

- The flips are made where Chromium registers the preferences, by changing the registered default, so every reader sees the same value and no migration runs.
- `search.suggest_enabled` is a syncable Chromium preference. The block's row toggles the same preference as Chromium's search-engine page.
- Global Privacy Control is Chromium's `GlobalPrivacyControlForce` feature, which every process reads from its command line at startup. Stedding adds it when the local-state preference is on (Q4).
- Still out of scope, each with a line in `docs/PRIVACY.md`: network time, translate, preloading, the component updater, and placeholder API keys in request URLs.
