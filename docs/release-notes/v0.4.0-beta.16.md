# Stedding 0.4.0 beta 16

Sync no longer makes copies of pinned tabs after a computer restarts, the Mac's window buttons
stay off the page, and History no longer offers Google sync. On Chromium 157.0.8103.51, a
security update.

## New

- **The window buttons stay off the page (Mac).** With the sidebar and the address row hidden,
  the red, yellow and green buttons hide while only the page lies under them. Rest the pointer at
  the window's top and they show until it leaves them; the address row, the open sidebar and a
  slide-in bring them back too (GitHub issue 93).
- **The window buttons in the address row in full screen (Mac).** In macOS full screen the
  buttons sit at the left of the address row, where the row is, not on a strip of their own above
  it.

## Fixed

- **Sync made copies after a restart.** A computer that quit and opened again sent its pinned
  tabs and essentials to the others as new ones, so a computer that had not restarted got a copy
  of each, most often from Windows to the Mac. A tab now keeps the id sync knows it by through
  every restart and every sleep. Copies made before this version stay until you remove them on one
  computer (GitHub issue 89).
- **History offered Google sync.** The History page had "Tabs from other devices", which asked to
  turn on Google's history sync, and the History menu offered a sign-in, though Stedding never
  signs the browser in to Google. Both are gone.
- **A little window grew on Windows.** At a display scale such as 150%, a little window that came
  back with a restart was a frame bigger at each launch. It now comes back at its size.
- **Homebrew's warning.** `brew` no longer warns about the cask's macOS requirement (fixed in the
  cask on 9 November, for every version).

## Security

- Chromium 157.0.8103.51, the stable point release with security fixes (from 157.0.8103.39).

## Install

- **macOS** (Apple silicon, macOS 13 or later): `Stedding-0.4.0-beta.16-arm64.dmg`, signed and
  notarized. Open it and drag Stedding to Applications.
- **Windows** (10 and 11, x64): `Stedding-0.4.0-beta.16-win-x64.exe`, installs for you alone.
  It is not signed yet: in SmartScreen click **More info**, then **Run anyway**, once.

Installed copies update themselves (Mac from 0.2.0 beta 16, Windows from 0.2.0 beta 19).

## Known limits

- The Windows installer is unsigned (`S-56`).
- Netflix, Disney+, Prime Video and Spotify's web player do not play yet (`S-270`).
- A Space that shares its session cannot have essentials of its own yet (GitHub issue 87, `S-445`).
- Finished downloads missing from the Downloads list (GitHub issue 90) are not understood yet; the
  steps that lead there would help.
- Sync through WebDAV or S3 was checked against local servers, not yet a commercial service. A
  server that only offers Digest sign-in is refused, and S3 uses path-style addresses.
- Arc's splits, archive and pinned folders were built from public descriptions of Arc's files and
  checked on files made to match them, not yet on a real Arc profile.
- Import from Opera was checked on files made to match Opera's, not yet on a real install.
- Dia's sidebar does not come across: Dia keeps it in an encrypted database.
- Making a real passkey with a finger on Touch ID was not tried.
- Chromium's tab search still jumps to a page in another window, with no question.
- Chromium's built-in list of sites that must load over HTTPS lapses for this build on
  10 January 2027; a release on a newer base comes before then.

## How it was checked

- **Suites:** on the Mac, 1492 unit tests and 948 browser tests on the release build and on the
  build with DCHECKs and the dangling-pointer detector. All passed on the release build. On the
  DCHECK build a page going full screen stopped at a check that the change to the window buttons
  in full screen had made untrue; the check now allows it, and release builds, which leave the
  check out, are unchanged. Eighteen tests that crashed or timed out together in that run passed
  twice alone. On Windows, 1480 unit tests on both builds, all passing, and 895 browser tests:
  on the release build all but two passed. One fails on the PC's 4K display at 150% at any scale
  (`S-458`), and one crashed once and passed 5 of 5 alone (`S-461`). On the DCHECK build, at the
  display's own scale, the geometry tests that read a DIP off at 150% failed as they do on the
  release build there (`S-458`), and a drag test that aimed while a Space switch still slid
  passes since its fix (`S-459`).
- **AddressSanitizer on Windows:** the unit and browser suites, with no AddressSanitizer report and
  no dangling pointer. The same 150% geometry tests failed, and a frame-timing test saw frames of
  0.28 s on the 4K display.
- **The fixes:** a History test failed on Chromium's own files and passes with the fix, and on the
  Windows build `chrome://history/syncedTabs` opens the history list. Two profiles syncing
  through a WebDAV place, with restarts and sleeps, made copies in tests that failed first and
  make none now. A little window kept its size through three launches at 150%.
- **Acceptance scripts:** the core loop on an installed Windows copy and on a copy of the
  notarized Mac build, all passing. On Windows, run right after the installer's cycle, one press
  on a folder's header left it open; alone, that part passed all fourteen steps.
- **Updates:** from beta 15 to beta 16 on both platforms through a local feed, the same files
  users get, with the sidebar's width kept on Windows.
