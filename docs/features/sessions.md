# Feature: Independent Space sessions

Status: **S1–S13, S16, S17, S19–S32 and S34–S36 built. S14, S15, S18 and S33 withdrawn.** S32's live look and sound checks have not run (`docs/features/acceptance.md`, "The session mark").
Owner docs: `docs/decisions/0019-space-sessions-are-storage-partitions.md`, `docs/PRODUCT.md` §2, `docs/features/spaces.md`, `docs/features/windows.md` G5.

A Space can keep its own cookies, HTTP cache and site storage, so the same site can be signed in with different credentials in different Spaces of one window. Off by default. Extensions, settings, history and saved passwords stay on the profile.

## What isolation is

Chromium shards cookies, cache, localStorage, IndexedDB and service workers by `StoragePartition`. An isolated Space's tabs are created in a non-default partition named by that Space's `profile_id` (`partition_domain` `spaces`, on disk). A Space with an empty `profile_id` uses the profile's default partition, which is what every Space does until isolation is turned on (S2).

Isolation is a property of the Space at tab creation. `window.open` inherits the opener's partition. A shared essential stays on the default partition. An essential pinned in a Space with an Independent session is that Space's own and uses its partition (S8, spaces B6, ADR 0028).

## Out of scope

A Chromium Profile per Space (separate extensions, history, prefs). Cookie-only swapping. Binding two Spaces to one jar. Extension `chrome.cookies` seeing isolated jars. Per-Space proxies or fingerprints. A persistent intern or model that holds a Space's cookies (ADR 0020). Temporary in-memory jars are `docs/features/throwaway.md`.
