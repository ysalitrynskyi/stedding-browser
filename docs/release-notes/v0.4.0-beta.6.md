# Stedding 0.4.0 beta 6

Peek over the page, Spaces that loop, the whole address row in the sidebar, and imports from
Chrome, Edge, Brave and Vivaldi. On Chromium 157.0.8103.31.

## Changed

- **Peek opens over the page** (GitHub issue 62). A link from a pinned tab to another site
  now opens on a card over the pinned tab's page, inside the window, as in Arc: no separate
  window to drag around. The pinned page waits, dimmed, until you close the peek, and the peek
  belongs to its tab: switch tabs and it hides, come back and it is there. Its bar has Open in
  Split View, Open as Tab and Close; Escape, ⌘W (Ctrl+W) or a click beside the card close it,
  ⌘O (Ctrl+O) keeps the page as a tab. The small window is still there: Settings › Stedding ›
  Peek and little windows › **Show a peek** › In a small window.
- **Spaces loop** (GitHub issue 66). After the last Space comes the first again, and before the
  first the last: with the keys, a swipe, the sideways wheel, and when you move a tab to the
  next Space. **Loop around Spaces** in Settings › Stedding › Spaces turns it off.
- **The whole address row moves into the sidebar** (a comment on GitHub issue 45). With
  **Show the address in the sidebar** on, the row's remaining buttons, your extensions and
  their menu, downloads and the other pinned buttons, and the menu, sit in a row under the
  sidebar's address, so the address row is gone while the sidebar is open. On Windows the
  window's own buttons (minimize, maximize, close) move to the top of the sidebar and show
  when the pointer is over it.
- **Import from Chrome, Edge, Brave and Vivaldi.** The welcome flow's import step finds them,
  as it finds Dia, with each profile's bookmarks, history and passwords in one click. Each
  other browser's row now shows only what it can bring, and Firefox's autofill data and
  Internet Explorer's search engines can come too. Settings › Stedding › Sync and import ›
  **Import from another browser** opens that step any time.

## New settings

- **Edge that shows a hidden sidebar**: Narrow, Medium (the default, wider than before) or
  Wide, for how far in from the window's edge the pointer can rest to bring a hidden sidebar
  in (a comment on GitHub issue 45).
- **Essentials per row** gains Up to 2.
- **Show a peek** and **Loop around Spaces**, above.

## Fixed

- **The sidebar's width after an update** (GitHub issue 65). Chromium rewrites its session file
  at every start and now and then while you browse, and the rewrite dropped the sidebar's
  width: the next restore from it, such as an update's restart, opened the sidebar at the
  default width and kept that. The width you set now survives, and a window with no width
  saved takes the one you set last.

## Install

- **macOS** (Apple silicon, macOS 13 or later): `Stedding-0.4.0-beta.6-arm64.dmg`, signed and
  notarized. Open it and drag Stedding to Applications.
- **Windows** (10 and 11, x64): `Stedding-0.4.0-beta.6-win-x64.exe`, installs for you alone.
  It is not signed yet: in SmartScreen click **More info**, then **Run anyway**, once.

Installed copies update themselves (Mac from 0.2.0 beta 16, Windows from 0.2.0 beta 19).

## Known limits

- The Windows installer is unsigned (`S-56`).
- Netflix, Disney+, Prime Video and Spotify's web player do not play yet (`S-270`).
- A peek over the page shows no permission prompt of its own; Open as Tab and allow it there.
- Opera is not offered on the import step.
- Chromium's built-in list of sites that must load over HTTPS lapses for this build on
  13 December 2026; a release on a newer base comes before then.

## How it was checked

Each change has tests of its own: a link peeks over the page inside the window, each way to
close a peek leaves the pinned tab as it was, Open as Tab and Open in Split View move the same
page, the peek goes and comes with its tab, "Leave site?" asks before a peek closes, and the
small window is still a choice; Spaces that loop; the sidebar's width through a rewrite of the
session file (that test fails without the fix); the hidden sidebar's edge; the address row's
buttons in the sidebar; and each browser of the Chromium family on the import step. On the final
build every unit and browser test passed on both platforms: on the Mac 1358 unit tests and 707
browser tests, on Windows 1349 unit tests and 666 browser tests, also with the extra checks for
dangling pointers and broken assumptions, and on Windows under AddressSanitizer, which found no
memory errors. On the Mac one new test of the sideways wheel failed in both runs: it checked a
step with motion off while the slide of the step before was still going. The test now waits for
that slide, and passes 3 of 3 runs on both platforms; no shipped code changed. With the real
keyboard and pointer on Windows: the address in the sidebar, the window's buttons there on
hover, and Maximize, Restore and Minimize from them; a peek's card, closed by Escape, Ctrl+W and
a click beside it, kept by Ctrl+O, and paired by Open in Split View; Spaces looping both ways by
key; the hidden sidebar coming in at the edge and going when the pointer leaves; and the import
step from the command bar, which found Arc, Edge and Vivaldi on that PC. With the real keyboard
and pointer on the Mac's signed build: Spaces looping both ways by key; a peek over the page,
closed by Escape, ⌘W and a click beside it, kept by ⌘O, and paired by ⇧⌘O; the hidden sidebar's
edge; and the import step from the command bar, which found Arc and Chrome on that Mac. The
acceptance scripts (the core loop, a relaunch, drags, keys) passed on Windows' installed copy
(39 of 39) and on the Mac's signed build, where a clipboard manager that was running took ⇧⌘C
and the ⌃⌘N after it; both chords' commands were checked on that build another way. Apple's
distribution check passed. On Windows an installed 0.4.0 beta 5 updated itself to this release
through a copy of the update feed and came back with its tabs, and the installer repaired,
uninstalled keeping the profile, and installed again.
