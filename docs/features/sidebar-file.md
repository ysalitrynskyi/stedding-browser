# Feature: Sidebar file

Status: **Sf2 and Sf6–Sf10, Sf12–Sf42 built**, with the gaps in the rows. **Sf11 is not built. Sf16 and Sf25 are partial. Sf1 and Sf3–Sf5 are withdrawn** (patch 0055). Sync through a folder is S-282, ADR 0029. Owner: import I18–I20.

The sidebar travels as a file. With sync on, each computer keeps its own file in a folder the user's sync tool or shared drive carries. No Stedding account, no Stedding host, no network request.

Settings › Stedding › Sync and import has three buttons. **Export Space…** writes the active Space. **Export all Spaces…** writes every Space of the window. Both go to Downloads. **Import sidebar…** reads either file back. The file is the importer's format (import I20, `sidebar_backup.cc`): Arc's shape, with what that shape has no place for in a block of its own. Importing merges. It adds what is missing and never closes, moves or renames anything that is open.

## What a file holds

The top level is Arc's: `sidebar.containers[1]` with `spaces`, `items` and `topAppsContainerIDs`, then `"version": 1` and `"writer": "Stedding"`. One parser reads Arc's file and Stedding's. `"writer": "Stedding"` is what makes an import merge by the durable ids (Sf2). A reader of Arc's shape skips the rest.

Each Space entry has a `stedding` block: `color` and `darkColor` (`#RRGGBB`), `isolated` (the Space has its own session; never its partition or anything in its jar), and `essentials`, the id of a top-apps container holding the essentials that are that Space's own. That container is not listed in `topAppsContainerIDs`.

A file never holds history, cookies, passwords, extensions, a Space's partition, routes, settings, child-tab nesting, splits or collapsed states.

A synced file is that export plus a `stedding_sync` block: the format number, the install id and name, a write number and a random value per write, the times, and `records`, `lists` and `aliases`. Each field is `[value, time, install]`. A removal is a `del` time. This computer's ledger and its five backups stay in the profile, not in the folder.

## Limits

- An import only adds. It does not rename, recolour, move, unpin or delete anything already here, and it does not change the session of a Space that exists. A folder already here keeps its place.
- A Space's own essential comes in as its own only when the Space has its own session here. Otherwise it joins the shared row.
- Arc's folders in a pinned run still come in under the Clear line. Only a file Stedding wrote says a folder was pinned.
- A computer away for more than 180 days can bring removed items back as additions. A large batch is held (Sf22).
- Pins in a closed window stay in the ledger and keep travelling. They come back through **Bring them here** (Sf20) or by reopening the window, until windows G2 (S-94) shows pins in every window.
- The order of pins inside a run, a folder or an essentials row is not applied to the windows (Sf16). A pin another computer added joins the end of its run.
- Not built: a computer first seen later asking before its same-named Space pairs (Sf11); waiting for a drag to end (Sf25); a notice that an item was kept because another computer changed it after it was removed here.
